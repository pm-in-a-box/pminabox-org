Product tour

What is in the box, feature by feature.

Every feature belongs to an agent, a department, or a person. That boundary is the design: it decides what an agent can see, what a manager can open, and what leaves the Box in an export.

This tour covers the hosted beta and the desktop experience under development. The desktop app is not yet publicly released, and feature availability may change during beta.

01

Agents

An agent that only answers questions is not worth keeping.

These are the behaviors that separate a useful agent from a chat window with a property management theme.

Memory that holds

Tell an agent your preferences, your style, or how your portfolio works and it keeps that without being asked to. It prunes what has gone stale, and you can open a remembered document or note and read the whole thing rather than a title.

Routines on a schedule

Ask for a Monday morning summary or a weekday debrief and the agent creates the routine itself. Its details panel lists what is scheduled, and every routine can be run now, paused, or deleted. A firing shows as a card with the instruction and the schedule.

Agent to agent work

A manager agent can brief a whole team without waiting on any single reply. Each teammate gets its own request, answers on its own time, and remembers the exchange in its own thread. Every hand-off renders as a card you can open and read.

Web search and reading

Every agent can search and read public pages with no setup and no extra connector. It reads a bounded number of pages per answer, names the ones it used, and is instructed to treat what it finds as information rather than instructions.

Compute and real files

Agents calculate over bounded data handles instead of guessing at arithmetic, and return reviewable CSV, XLSX, PDF, and document output to the conversation that asked for it.

Skills, models, and proposals

Attach focused skills, choose from the models available to the Box, and watch the tool activity behind an answer. An agent can propose a reusable improvement to its own instructions, and nothing changes until a person approves it.

02

Solo and team

Two places, two casts, one set of connectors.

A tab at the top of the app switches between them. Neither can message into the other.

Single Player

Your own agents on a left rail, one large conversation on the right. No channels, no presence, nothing shared. Each agent owns a private thread and a private memory scope, so the marketing agent and the manager agent do not know the same things.

A roster you own

Add as many agents as you want and delete any of them, including all of them. Connectors belong to your workspace rather than to an agent, so no single agent is load bearing. Rename, recolor, or pause one from its context menu.

A face per agent

Pick from twenty characters and twelve colors, or leave it on Auto and every agent still gets a distinct look. The look follows the agent, so renaming one does not change how you recognize it.

Department channels

In Multiplayer, each department is a live room with messages, threads, reactions, mentions, attachments, presence, search, and voice calls. A room also owns its board, email, calendar, automations, agents, skills, model, and connectors.

Direct and group conversations

Send direct messages, create private group chats, and start voice calls. These do not invoke department agents and stay outside shared Box exports.

The Warehouse

A cross-Box lobby where property managers share questions, answers, and useful work while company operations stay in their own Box.

03

Work

Conversation turns into owned work.

Tasks, inboxes, and calendars live beside the discussion that created them.

Department task boards

Create lanes that match the real workflow. Assign people and departments, set dates and priority, add subtasks and comments, attach files, link properties, and move work through completion.

Reusable task templates

Save recurring checklists as department-owned templates. Applying one creates an independent task with the current description and subtasks, so later template edits never rewrite work in progress.

My Tasks

See assigned tasks, department work, approvals, and related activity in one personal queue. A task can move between departments without losing its history or attachments.

Shared and personal email

Read threads, compose replies, and send from Google Workspace or Microsoft 365. Shared mail belongs to a department. Personal mail stays with the person.

Calendar work

List and create events, update schedules, check attendee availability, and find open meeting times. Calendar access uses the same department or personal scope as email.

Files with context

Attach source material to chats and tasks. Agents can work with text, images, PDFs, Word documents, and spreadsheets within explicit size and context limits.

04

Automation and apps

Build the repeatable part. Keep the judgment visible.

Automations and Box Apps are department-owned, reviewable, and versioned.

Visual flow builder

Connect triggers, conditions, AI prompts, web research, email drafts or sends, chat messages, and task actions on a canvas your team can inspect. A flow can wake an agent to triage a new record.

Test before activation

Simulate a flow without posting or emailing. AI and research steps can run against the test input, and run history shows what started a flow, which node ran, what it produced, and where it failed.

Box Apps that act

Ask the protected Engineering agent for an internal app, and choose the home department and the exact connector data it may use. Apps save work now: task stages, notes, checklists, and governed connector writes. Drafts stay private until published.

App permissions and safe data

Set viewers, operators, and managers per app. Every action pins its target, minimum role, and original grant. An app receives only the fields declared on its immutable version, never a session token or a connector credential.

Website studio

Marketing can read an existing site, create a fresh homepage, refine it with plain-language requests, compare versions, preview each one, publish, and attach a custom domain.

Agent-proposed automations

A repeated request can become a reviewable automation proposal. Nothing runs until a person accepts the proposed flow.

05

Data and connectors

Use business data without flattening its boundaries.

Each connector belongs to one department or one person. The server holds the credential.

Live first, stored fallback

An agent reads the connected system live and falls back to compatible stored data when a provider is unavailable. The reply says when stored data was used, and how fresh and complete it was.

Continuous connector mirrors

Supported connector data syncs into a department-owned mirror for search, agents, reports, automations, and exports. Freshness and partial coverage stay visible instead of being smoothed over.

Portfolio reports

Ask an agent to run a verified report recipe. Property, unit, owner, and rent-roll data produce matching PDF and spreadsheet artifacts from one immutable run, with data exceptions listed.

Portable Box export

Owners can build a machine-readable archive of shared chats, tasks, configuration, membership, connector metadata, and imported business records, including RealPage data. Missing source objects fail the export visibly.

Private data stays out

Personal workspaces, direct messages, private group chats, connector secrets, session capabilities, and MCP tokens are excluded from the owner-wide export.

Storage that scales

Imported business records live in a substrate built for portfolio-sized data, so search and agent reads stay bounded as the archive grows.

06

Access and control

Use the box from elsewhere, and manage it without reading private work.

MCP access

Create a revocable personal token for Codex CLI, Claude Code, Cursor, Claude Desktop, or another Model Context Protocol client. The token acts as the member who created it.

Computer use

Pair the bundled Chrome companion to let the workspace-level browser agent navigate, list and focus tabs, click, type, capture screenshots, and extract visible page content.

Marketplace

Browse, test, publish, install, update, and remove community agents and skills. Listings disclose their full instructions and connector requirements before install, and every install arrives as a draft.

People and department access

Invite members, assign roles, and grant explicit department membership. Connector audiences are visible before authorization and after setup.

Adoption oversight

See last login, last meaningful work, and content-view receipts. Hierarchical work-inbox review is audited and excludes personal conversations, email, calendars, and connector data.

Debug IDs and traces

Agent replies carry a support debug ID. If a customer shares that exact ID, authorized support can inspect the bounded run trace. Cross-Box access is restricted and audited.
